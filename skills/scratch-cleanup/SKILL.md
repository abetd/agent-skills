# scratch-cleanup

`.scratch/` 直下のファイル（sounding-board・review-triage・explainer が置いたものに加え、手で置いたプランファイルなども含む）のうち、もう使わなさそうなものを**候補として一覧にし、ユーザーが外したもの以外を片付ける**。

- 片付けは基本**アーカイブ**（`.scratch/archive/` に移す）。消すのはユーザーが削除を選んだときだけ
- 一覧は**全部を片付ける前提**で出し、ユーザーは残したいものを番号で外す
- `.scratch/` は git で管理されていても、**git には触らない**（普通に移す・消すだけ。コミットするかはユーザーが決める）

---

## ステップ 1: `.scratch/` を探す

リポジトリルート（`git rev-parse --show-toplevel`）の `.scratch/` を対象にする。以下のコマンドの `<ルート>` はここで取ったパスで、カレントディレクトリがサブディレクトリでも同じ場所を見るよう、`.scratch/` は必ず `<ルート>/.scratch/` と書く。

- `.scratch/` が無い・git リポジトリの外なら、片付けるものが無いと告げて終わる。`.scratch/` を作らない
- `.scratch/` は symlink のこともある。パスは末尾に `/` を付けて扱い（`.scratch/`）、リンク先を辿る

## ステップ 2: 動き方を決める

次の 4 つから 1 つ選ぶ。

| 動き方 | 候補 | 片付け方 |
|---|---|---|
| アーカイブする | `.scratch/` 直下（ステップ 3-1） | `.scratch/archive/` に移す |
| 直下を削除する | `.scratch/` 直下（ステップ 3-1） | 消す |
| アーカイブ内をすべて削除する | `.scratch/archive/` 内のすべて | 消す |
| アーカイブ内の古いものを削除する | `.scratch/archive/` 内で、最後の更新から n 日たったもの | 消す |

- 依頼文や引数で動き方が分かるとき（「アーカイブを全部消して」など）は聞かない
- 分からなければ AskUserQuestion で 4 つから選ばせる。削除の 3 つの description には、消したものは戻せないことを書く
- n の既定値は **30 日**。引数や依頼文に日数があればそれを使う
- アーカイブに移しても更新日時は変わらない。そのため「アーカイブ内の古いもの」も、最後の更新から数える。既定の 30 日ではアーカイブしたものがほとんど当たるので、絞りたいときは長めの日数を渡すよう告げてよい

## ステップ 3: 候補を集める

### 3-1. 直下の候補（アーカイブする・直下を削除する）

対象は `.scratch/` 直下の**通常ファイルすべて**（`.html` に限らず `.md` なども含む）。ディレクトリ（`archive/` など）と、`.` で始まる隠しファイルには触らない。

次のどれかに当たるものを候補にする。複数に当たれば理由を併記する。

| 理由 | 当たるもの | 使う範囲 |
|---|---|---|
| **n 日更新なし** | 最後の更新から n 日以上たったファイル（`find <ルート>/.scratch/ -maxdepth 1 -type f ! -name '.*' -mtime +<n-1>`） | すべてのファイル |
| **ブランチがマージ済み** | review-triage のボードで、そのブランチが既定ブランチにマージ済み | 今のリポジトリのものと分かるボードだけ（3-2） |
| **ブランチが無い** | review-triage のボードで、そのブランチがローカルにもリモートにも無い | 同上 |
| **新しい版がある** | explainer の説明資料で、同じトピックの資料（`dns-explainer.html`・`dns-explainer-2.html` …）が直下に複数あるとき、最後の更新がいちばん新しいもの以外。連番の大小では決めない（アーカイブで連番なしの名前が空くと、explainer は次の資料をその名前で書くため） | すべての説明資料 |

**説明資料の見分け方**: ファイル名が `-explainer.html` か `-explainer-<数字>.html` で終わり、かつ sounding-board のボードでないもの。sounding-board のボード名は自由な kebab-case なので、名前だけでは分けきれない（`improve-explainer.html` など）。sounding-board のボードはテンプレートの `<style>` を丸ごと複製しているので完了バナーの CSS 定義 `.done{` を持ち、説明資料は持たない。これで見分ける（レビューボードは先に 3-2 の見出しで除いておく）。

`.scratch/` はほかのリポジトリと共有されていることがある（symlink で同じディレクトリを指すなど）。ブランチの条件は、別のリポジトリのボードに使うと「ブランチが無い」と誤って判定するので、今のリポジトリのものと分かるボードに限る。日数と新しい版の条件はファイルだけで決まるので、どのリポジトリのものでも使う。

### 3-2. レビューボードを読み分ける

ヘッダーの見出しが `レビュー:` で始まる HTML を review-triage のボードとして扱う（ファイル名は `*-review.html`）。

- **ブランチ**: 見出しの `レビュー: ` の後ろから、` — `（変更内容の一言の前）の手前まで。ファイル名はブランチの `/` を `-` に置き換えているので、ファイル名からは取らない
- **どのリポジトリのものか**: ヘッダーの base とコミットの欄に書かれたコミットハッシュ（7 桁以上の 16 進数）を、`git cat-file -e <ハッシュ>^{commit}` で引く
  - 1 つでも引ければ今のリポジトリのもの
  - ハッシュがあってどれも引けなければ別のリポジトリのもの
  - ハッシュが無ければ分からない。ブランチの条件は使わない
- **既定ブランチ**: `git symbolic-ref --short refs/remotes/origin/HEAD` から取る（`origin/` を外す）。取れなければ `main`、無ければ `master`
- **マージ済み**: ローカルにブランチがあれば `refs/heads/<ブランチ>`、無ければ `'refs/remotes/*/<ブランチ>'` が、`git for-each-ref --merged <比較先> <その ref>` に出る。比較先は `origin/<既定ブランチ>`（無ければローカルの `<既定ブランチ>`）にする。ローカルの既定ブランチを pull していなくても、リモートにだけ残るブランチでも拾えるようにするため
- **ブランチが無い**: `git rev-parse --verify --quiet refs/heads/<ブランチ>` も、`git for-each-ref 'refs/remotes/*/<ブランチ>'` も空
- ボードのブランチが既定ブランチそのもの（main 上の変更をレビューしたボード）なら、ブランチの条件は使わない（いつでも「マージ済み」になるため）。日数の条件だけで判定する

squash マージでブランチを残している場合は、ブランチの条件では拾えない。日数の条件で拾われるのを待つ。

### 3-3. 初めから外しておくもの

候補のうち、次のものは一覧に**印（`残す`）を付け、初めから外した状態**で出す。片付けるならユーザーが番号で戻す。

- **凍結前のボード**: レビューボードでも説明資料（3-1 の見分け方）でもない HTML で、`<header>` 内のコメントの外に完了バナー `<div class="done">` が無いもの（sounding-board の議論が続いている）。`.done{...}` の CSS 定義は凍結前のボードの `<style>` にもあるので、凍結の判定には使わない（説明資料との見分けにだけ使う）
- **今のブランチのレビューボード**: 3-2 で今のリポジトリのものと分かり、ブランチが今のブランチ（`git branch --show-current`）と同じもの

### 3-4. アーカイブ内の候補（アーカイブ内を削除する）

`.scratch/archive/` 直下の通常ファイルが対象。「すべて」ならそのまま全部、「古いもの」なら最後の更新から n 日以上たったものだけ（`find <ルート>/.scratch/archive/ -maxdepth 1 -type f ! -name '.*' -mtime +<n-1>`）。3-3 の印は付けない（一度片付けたものなので）。

`archive/` が無い・空なら、消すものが無いと告げて終わる。

## ステップ 4: 一覧を出して、外すものを聞く

候補が 1 つも無ければ、片付けるものが無いと告げて終わる。

候補があれば、チャットに**番号つきの表**を出す。並びは更新日の古い順。

| 列 | 中身 |
|---|---|
| # | 1 からの番号 |
| ファイル | ファイル名 |
| 理由 | 3-1 の理由（複数なら併記）。アーカイブ内なら「アーカイブ内」 |
| 更新日 | 最後の更新日 |
| リポジトリ | 「このリポジトリ」「別のリポジトリ」「不明」（3-2。レビューボード以外は「不明」） |
| 状態 | 片付けるものは空欄、初めから外したものは `残す`（3-3 の理由を添える） |

表の下で、動き方と片付ける件数を一行で書き（例: 「11 件を `.scratch/archive/` に移します」「5 件を削除します。消したものは戻せません」）、次のように聞いて**ユーザーの返事を待つ**:

- 外すものを番号で（例: `3,5`）
- `残す` を戻して片付けるなら `+` を付けた番号で（例: `+4`）
- 無ければ「このまま」

返事に従って対象を決め直す。番号と別の指示（日数を変える、動き方を変えるなど）が返ってきたら、それに合わせて候補を集め直し、一覧を出し直す。片付ける対象が 0 件になったら、何もせずに終わる。

## ステップ 5: 片付ける

- **アーカイブ**: `.scratch/archive/` が無ければ作る（`mkdir -p <ルート>/.scratch/archive`）。移す前に `archive/` に同じ名前のファイルがあるかを確かめ、あれば拡張子の前に連番を付けた名前で移す（`foo.html` → `foo-2.html`、それもあれば `-3` …）。上書きはしない。確認から漏れても上書きしないよう、`mv` には `-n` を付ける。移すと更新日時はそのまま残る
- **削除**: `rm` で消す。ゴミ箱を経由しない
- まとめて 1 回のコマンドで移す・消す（`mv -n <ファイル>… <ルート>/.scratch/archive/`、`rm <ファイル>…`）。連番を付けるファイルだけ個別に `mv` する。シェルのループ（`for` / `while`）は使わない
- git のコマンド（`git mv`・`git rm`・`git add` など）は使わない
- 実行したら、対象の元のファイルが元の場所（直下、またはアーカイブ内）に残っていないこと（`ls` で確かめる）と、アーカイブなら `archive/` に移した名前で入っていることを確かめる。`mv -n` は同じ名前があると黙って移さないので、残ったものは失敗として扱う

## ステップ 6: 結果を告げる

- 移した・消した件数と、それぞれのファイル名（連番を付けたものは新しい名前も）
- アーカイブしたときは、`archive/` に移したボードはほかのスキル（sounding-board の再開・review-triage の再レビューや仕様の候補・explainer の連番）からは見えなくなること。戻すときは `.scratch/` 直下に移し戻せばよい。連番を付けて移したものは、元の名前に直して戻す（再開・再レビューはファイル名で探すため）
- 失敗したものがあれば、そのファイルと理由

---

## やらないこと

- `.scratch/` を作ること
- 一覧を見せず、ユーザーの返事を待たずに片付けること
- ディレクトリ・隠しファイルを片付けること
- `archive/` 内の同じ名前のファイルを上書きすること
- git のコマンドで移す・消す・ステージすること
- 別のリポジトリのものかもしれないレビューボードに、ブランチの条件を使うこと
